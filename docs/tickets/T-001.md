# T-001: Settle up with the greedy method

Status: open
Milestone: M1
Risk: high
Issue: #4

## Goal

A member can run `tally settle-up` and get a list of payments that clears every balance, at most n−1 of them, without the ledger changing.

## Done when

1. On random ledgers (seeded `random.Random`, at least 500 cases), applying every payment from `settle_up(balances)` brings each balance to exactly 0 cents; every amount is a positive integer and there are at most n−1 payments, where n is the number of members with a non-zero balance. Covers the money-calculation sensitive area. Checked by `.venv/bin/python -m pytest -q tests/test_settle.py`.
2. The result is deterministic: the same balances always give the same payments, ties broken by member order as first added. Checked by a test in `tests/test_settle.py`.
3. `tally settle-up` prints one line per payment as `<from>\t<to>\t<amount>`, with amounts formatted like `tally balances` (`cents()`), and a note on stderr that the result may not be the minimum number of payments. Checked by a test in `tests/test_cli.py`.
4. `tally settle-up` never writes the ledger file: its bytes are identical afterwards. Checked by a test in `tests/test_cli.py`.
5. When every balance is 0, it prints nothing on stdout and exits 0. Checked by a test in `tests/test_cli.py`.
6. The full test command passes: `.venv/bin/python -m pytest -q`.

## Depends on

## Assumptions

- Greedy method: repeatedly the largest debtor pays the largest creditor the smaller of the two amounts; ties go to the member added first.
- `settle_up` takes the `dict[str, int]` that `Ledger.balances()` returns (display names, member order) and returns a list of `Payment(payer, receiver, amount)`; it does no I/O.
- Property tests use seeded `random.Random` loops in plain pytest, not Hypothesis (D-5).
