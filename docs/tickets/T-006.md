# T-006: Refuse malformed ledger files

Status: done
Milestone: M2
Risk: high
Issue: #22

## Goal

tally refuses every ledger file it can't read correctly, with a `TallyError` that says what is wrong, and never rewrites it. Today a version 2 file without `entries` loads as an empty ledger and the next save writes it out empty, losing every entry without an error (raised by both T-003 verifiers, PR #19).

## Done when

1. A file with `"version": 2` and no `entries` list (with or without a leftover `expenses` key) makes every command (`balances`, `settle-up`, `add-member`, `add-expense`, `settle`) exit 1 with `error: ` and a message naming the missing `entries`; the file's bytes and mtime are unchanged. Checked by `tests.test_cli::test_v2_file_without_entries_is_refused`. (S-16)
2. A file with no `version` but an `entries` key is refused the same way (it is a version 2 body, not a v0.1 file), naming `version`. Checked by `tests.test_cli::test_entries_without_version_is_refused`. (S-17)
3. A file that isn't valid JSON, or whose top level isn't a JSON object (`[]`, `"x"`, `3`), exits 1 with `error: ` and one line naming the problem, with no Python traceback on stderr; the file is unchanged. Checked by `tests.test_cli::test_unreadable_or_non_object_file_is_refused`. (S-18)
4. An entry (version 2) or an expense (v0.1) that isn't an object, or lacks a field its kind needs (`payer`, `amount`, `participants` for an expense; `payer`, `receiver`, `amount` for a settlement), raises a `TallyError` naming the entry's position (counting from 1) and the field; nothing is recorded or written. Checked by `tests.test_ledger::test_malformed_entries_are_refused`. (S-19)
5. Each of conditions 1 to 4 has at least one assertion that compares the whole message, not a prefix or substring (learning 1; verifier checklist item 6).
6. The full test command passes: `.venv/bin/python -m pytest -q`. (S-14)

## Assumptions

- Validation lives in `Ledger.from_dict` (D-11's home for version handling); `cli.load` turns `json.JSONDecodeError` into a `TallyError`. Both raise before any command can reach `save`.
- The exact wording of each message is the builder's choice, recorded in the decision log; the tests pin whatever it is.
- T-005 adds the `settlement` kind, so this ticket runs after it and checks settlement fields too.
- Sensitive area: the ledger file format. Every condition guards it.
- Before this ticket is built, `main` must be merged into `milestone/M2` so this file is on the milestone branch (pitaya's P14).
