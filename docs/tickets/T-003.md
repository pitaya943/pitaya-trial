# T-003: Versioned ledger file format

Status: open
Milestone: M2
Risk: high
Issue: #15

## Goal

Ledger files carry `"version": 2` and keep expenses in one ordered `entries` list, so later milestones can change the format safely. v0.1 files still load with identical balances and are upgraded on the next save; any other version is refused instead of misread.

## Done when

1. A save writes `"version": 2` and an `entries` list where each item has `"kind": "expense"`; `to_dict` → `from_dict` keeps the entries in recorded order. Checked by `tests/test_cli.py::test_cli_writes_version_2` and `tests/test_ledger.py::test_round_trip_keeps_entries_in_order`. (S-6)
2. `tests/fixtures/v0.1.json` exists and was written by the v0.1 code (see Assumptions). `tally balances` on it prints exactly the balances hard-coded in the test. Checked by `tests/test_cli.py::test_v01_fixture_loads_with_the_same_balances`. (S-7)
3. `balances` and `settle-up` on a copy of the fixture leave its bytes and mtime unchanged. Checked by `tests/test_cli.py::test_read_only_commands_do_not_upgrade_a_v01_file`. (S-8)
4. A saving command (`add-member Dee`) on a copy of the fixture writes `"version": 2`, keeps the old members' balances identical and keeps the expenses in order. Checked by `tests/test_cli.py::test_v01_file_is_written_as_version_2_on_save`. (S-9)
5. A file with `"version": 3` or `99` makes every command exit 1 with a `TallyError` naming the version; the file's bytes and mtime are unchanged. Checked by `tests/test_cli.py::test_unknown_future_version_is_rejected_and_not_written`. (S-10)
6. `Ledger.from_dict` raises a `TallyError` naming the value for `version` `1`, `0`, `"2"`, `null` and `true` (`true` must not be taken as 1). Checked by `tests/test_ledger.py::test_unsupported_version_values`. (S-11, D-11)
7. The full test command passes: `.venv/bin/python -m pytest -q`. (S-14)

## Assumptions

- Interfaces come from the design: `FORMAT_VERSION = 2`, `Ledger.entries` as the one owner of recorded order, `Ledger.expenses` as a read-only view filtered from `entries` (ADR 0003). `Settlement` arrives in T-005, not here.
- The fixture is generated by running the v0.1 `tally` CLI from `main` before `ledger.py` changes, and committed in the first commit together with its expected balances. It covers remainder splits, a subset of participants, mixed-case and padded names, and notes. The test hard-codes the balances; it doesn't recompute them with the new code (learning 1).
- "Bytes and mtime unchanged" checks use a hand-formatted file the writer would reformat, as in `test_cli_settle_up_keeps_a_hand_formatted_ledger_untouched` (learning 1).
- Sensitive area: the ledger file format. Conditions 2, 4 and 5 cover it.
