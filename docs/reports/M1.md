# Report: M1 — Settle up

Written by `/pitaya:report M1` on 2026-11-20 against `main` at `e507821`.

## Conclusion

Users can run `tally settle-up` to get a list of payments that clears every balance, without the ledger changing. For groups of up to 12 members with a non-zero balance the list is the true minimum number of payments; above that it uses the greedy method (at most n−1) and says so on stderr. All six exit criteria are met; criterion 4 is checked on `settle_up` rather than by running the CLI twice, which the Owner accepted (D-8).

## How to verify

1. `.venv/bin/python -m pytest -q` → `885 passed`.
2. In an empty directory write `tally.json`:
   `{"members": ["A","B","C","D","E"], "expenses": [{"payer":"A","amount":300,"participants":["D"]}, {"payer":"A","amount":200,"participants":["E"]}, {"payer":"B","amount":400,"participants":["C"]}]}`
3. `PYTHONPATH=<repo>/src python3 -m tally.cli balances` → `A 5.00, B 4.00, C -4.00, D -3.00, E -2.00`.
4. `... settle-up` → `D A 3.00`, `E A 2.00`, `C B 4.00`; exit 0; nothing on stderr (greedy would need 4 payments).
5. Run `settle-up` twice and `cmp` the outputs → identical. `sha1sum tally.json` before and after → unchanged.
6. With 13 members who all have a non-zero balance, stderr shows `note: greedy method; this may not be the minimum number of payments`.

## Decisions the agents made

- The stderr note prints only when there is at least one payment ([#7](https://github.com/pitaya943/pitaya-trial/pull/7) decision log).
- Each property-test seed is its own test ID, so the suite grew from 21 to 885 ([#7](https://github.com/pitaya943/pitaya-trial/pull/7)).
- Random test ledgers are built from zero-sum groups so exact and greedy actually differ ([#8](https://github.com/pitaya943/pitaya-trial/pull/8)).
- The exact method is an O(n·2ⁿ) prefix DP, not the O(3ⁿ) ADR 0001 states; the cap is unchanged ([#8](https://github.com/pitaya943/pitaya-trial/pull/8)).
- `uses_exact()` is exposed for the CLI instead of changing `settle_up`'s return type ([#8](https://github.com/pitaya943/pitaya-trial/pull/8)).
- Recovery takes the lowest index first; which of several optimal groupings is chosen is mostly not pinned by tests ([#8](https://github.com/pitaya943/pitaya-trial/pull/8)).

Owner decisions: D-5, D-6, D-7 and D-8 in `docs/decisions.md`.
